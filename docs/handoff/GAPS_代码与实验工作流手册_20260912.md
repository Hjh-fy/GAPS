## 1. 先用五分钟理解项目

GAPS 是一个面向跨设备电子鼻的云—边—传感器研究与部署框架。当前论文主线不是一个单独的分类器，而是一条完整生命周期：

```text
原始传感数据
→ 冻结预处理和数据角色
→ C1/C2 source Flower 联邦训练
→ C3/C4/C5 target commissioning
→ 气体类别路由
→ 定量浓度回归
→ QC accept/review/reject
→ 部署打包、Pi 5 基准和论文证据
```

接手项目时必须先区分两条互不替代的模型路线：

| 路线 | 当前输入合同 | 当前用途 | 能否相互复用 |
|---|---|---|---|
| 公共数据模型 | 原始数据约 100 Hz；canonical-v1 重新采样为 5 Hz、50×8 窗口 | 论文实验、离线回放、部署一致性和 UI 验证 | 不能直接部署成实验室 1 Hz 模型 |
| 实验室模型 | 未来采集板约 1 Hz；传感器、通道语义和预处理合同尚待正式冻结 | 未来真实实验室在线闭环 | 必须重新采集、训练、校准和封装 |

因此，目前不能声称已经完成：

- 实验室 1 Hz 正式模型和真实在线推理验收；
- 带 MCU 时间戳、帧序号和 CRC 的新版通信协议；
- 公共约 100 Hz 原始数据链路的真实 STM32 在线推理；
- 在线联邦训练、云端模型下发和 OTA；
- 经正式验证的全自动 QC 决策。

当前较稳妥的科学定位是：跨设备 sensing lifecycle、commissioning 和 observability 框架。不要写成“所有算法、所有设备、所有任务均优于所有基线”。

### 3.3 分类输入和定量特征

分类网络输入是 50×8 时序窗口。定量回归使用从同一 canonical 窗口重新计算的统计特征：

| 名称 | 含义 |
|---|---|
| 83D | 传感器统计特征 |
| 104D H1 | 83D + 21D protocol/phase/metadata 描述 |
| R84 | 83D canonical 特征 + 1D 冻结的 H1 source prior |

21D metadata 不是新增 21 个传感器通道。`slope`、`absdiff_mean/max` 只解释为 fixed-5-Hz discrete dynamic descriptors；不声明它们跨采样率不变，也不声明 legacy 10 Hz/100×8 与 canonical 5 Hz/50×8 数值等价。

## 4. 从数据到论文结果的正式工作流

### 4.1 阶段 0：先冻结协议

每个正式研究在运行前应固定：

- experiment/study ID；
- source/target 和 split；
- 数据 aggregate hash；
- seed、rounds、local epochs、batch size；
- optimizer、learning rate、loss 权重；
- target calibration 可访问字段；
- fixed endpoint 和 test 打开条件；
- checkpoint、结果目录和停止规则。

优先读取该研究目录中的：

```text
PROTOCOL.md
protocol_manifest.json
EXPERIMENT_PLAN.md
EXPERIMENT_MATRIX.csv
EXPERIMENT_REGISTRY.csv
PRE_EXECUTION_AUDIT.md
```

### 4.2 阶段 1：source Flower 分类训练

正式 canonical A4 配置为：

```text
source=C1,C2
rounds=25
local_epochs=1
batch_size=32
optimizer=Adam
learning_rate=5e-4
seed=42
checkpoint=fixed round25
```

Flower server 与两个 source client 由 Windows 控制器编排。训练阶段不应打开 target test。核心调用链：

```text
scripts/run_iotj_canonical_v1_classification.py
  → scripts/run_iotj_final_classification_le1.py
    → gaps_flower/server_app.py
    → gaps_flower/client_app.py
    → gaps_flower/strategy.py
```

### 4.3 阶段 2：target commissioning

每个 target 使用自己的 calibration pool 进行已经注册的 adaptation。不同方法允许访问的信息不同：

- canonical CORAL/MMD/DANN：target x only；
- A0T：target calibration class label 进入 target CE；
- A4：按协议使用 calibration x/class/phase；不使用 target concentration；
- class-conditional 诊断：class label 只用于类别分组；若是 `+TCE` 才额外进入 target CE。

target test 只能在全部固定端点完成后一次性打开，用于最终评价；不得用于调参、early stopping、threshold selection 或 checkpoint selection。

### 4.4 阶段 3：分类评价

主要指标：Accuracy、Macro-F1、NLL、ECE。评估脚本会加载固定 checkpoint，产生 metrics、逐窗口 prediction 和 source/target gap。常用入口：

```text
scripts/evaluate_iotj_canonical_v1_classification.py
scripts/evaluate_iotj_canonical_v1_comparators.py
scripts/evaluate_iotj_final_classification_le1.py
gaps_flower/evaluate_checkpoint.py
```

### 4.5 阶段 4：回归 R0 → R1 → R2

```text
R0-v2：验证 pooled Ridge 与 sufficient-statistics FedRidge 的数值/代数等价
R1：canonical 83D 与 R84 对比，并做 grouped bootstrap
R2：只在 R1 暴露 device/gas negative transfer 后检查 transfer-safe 候选
```

当前均已结束：R0-v2 PASS；R1 结论为 device-dependent；R2-v2 未找到能替代 R84 的安全候选，因此保留 R84，但必须带设备/气体依赖限定。

### 4.6 阶段 5：QC Q0 → Q1

```text
Q0：比较 classification confidence、regression uncertainty、multi-signal 风险
Q1：检查 conformal-style interval 是否足以改变冻结 QC 选择
```

最终 QC 为 confidence-only：

```text
r_cls = 1 - max_g p(g|x)
ACCEPT iff r_cls <= calibration-only empirical HC90/HC95 threshold
```

prediction interval empirical coverage 与 selective-output accepted coverage 是两个不同概念，论文中不能混写。

### 4.7 阶段 6：汇总、审计和论文证据

`scripts/consolidate_current_authoritative_results.py` 只读读取 sealed R1/Q0/Q1/R2 证据，生成统一 CSV、provenance index 和 hash。它不训练、不加载 checkpoint 推断，也不重新选择 QC。

统一结果入口：

```text
results/iotj_canonical_v1_final/current_authoritative_summary_20260812/
```

目标目录已经存在，汇总器会 fail closed，当前不要重复生成同名目录。

## 7. 最新 C5 六组 DA 诊断：如何理解

### 7.1 这不是 canonical 主表替代实验

Study：`C5-LABELED-CONDITIONAL-DA-PROBE-20260824`。

它固定使用：

```text
data: legacy client_data_c1234src_c5tgt_2080_timeaware_60_170_window_fullgrid
source checkpoint: P0A pure-FedAvg round25, LE1, seed42
checkpoint SHA256: 4313c375a8fa2e929de9d65637a2196f6c0f0752c2dc78112020b8727351751c
C5 calibration/test: 320/1360
steps: 100
optimizer: Adam, lr=5e-4
batch size: 32
alignment weight: 0.5
fixed endpoint: step100
```

三组 `+TCE`：

```text
CORAL+TCE = source CE + 0.5 global CORAL + 1.0 target CE
MMD+TCE   = source CE + 0.5 global MMD² + 1.0 target CE
DANN+TCE  = source CE + 0.5 global domain BCE/GRL + 1.0 target CE
```

三组 class-conditional without TCE：

```text
CC-CORAL = source CE + 0.5 true-class conditional CORAL
Class-MMD = source CE + 0.5 true-class conditional MMD²
CC-DANN = source CE + 0.5 shared-discriminator true-class conditional DANN
```

后面三组仍使用了 target class label 做条件分组，所以它们不是无监督方法；只是没有 target CE。

### 7.2 结果

| Method | C5 Accuracy | Macro-F1 | NLL | ECE |
|---|---:|---:|---:|---:|
| CORAL+TCE | 96.838% | 96.840% | 0.1437 | 0.0181 |
| MMD+TCE | 96.471% | 96.480% | 0.1744 | 0.0192 |
| DANN+TCE | 96.765% | 96.773% | 0.1556 | 0.0171 |
| CC-CORAL | 38.382% | 27.544% | 4.6570 | 0.6022 |
| Class-MMD | 88.382% | 88.514% | 0.5188 | 0.0673 |
| CC-DANN | 35.735% | 29.180% | 4.3158 | 0.6088 |

解释：

- 加入 target CE 后三种方法都从弱 x-only C5 区间升至约 96.5–96.8%；
- 但仍比 Simple Target-CE 低约 0.81–1.18 个百分点，说明主要收益来自标签监督，额外 global alignment 在固定配置下没有增益；
- 不加 target CE 时，只有 Class-MMD 明显受益；CC-CORAL 没有改善，CC-DANN 反而更差；
- 这些只是 seed42 mechanism diagnostic，不能证明多 seed 稳定性；
- 原 TABLE II 的 x-only CORAL/MMD/DANN 行保持不变。

### 9.5 checkpoint 的两种 hash

## 14. 当前局限和下一步建议

### 14.1 科学局限

- 多数正式主比较为 seed42，不能主张充分的跨 seed 稳定性；
- canonical target split 为冻结的 window-level 20/80，不能扩大解释为严格 raw-file-disjoint 泛化；
- equal-label 研究不支持 A4 的普遍 label-efficiency advantage；
- source-DG、commissioning bridge 和 cost-aware routing 的已注册验证没有形成新主线；
- R84 在 pooled、C3、C4 有改善，但 C5 CI 跨 0，gas 级存在 negative transfer；
- regression uncertainty 有排序信息，但没有推翻冻结的 confidence-only QC；
- 最新 labeled/class-conditional DA 只是 legacy C5 seed42 机制诊断。

### 14.2 工程局限

- 三机运行依赖 SSH、专用 venv、隧道和冻结数据 hash；
- Pi 局域网 IP 可能变化；
- `results/` 很多文件不受 Git 跟踪；
- 名称含 `final` 不代表仍然 authoritative；
- 远端 checkout 和正式 hash runtime 可能不同；
- 当前公共数据运行时不能直接用于未来 1 Hz 新采集板。

### 14.3 当前建议

当前没有必要继续自动扩展算法。更合理的下一步是：

1. 将论文正文、TABLE II、回归表、QC 图与 authoritative summary 对齐；
2. 做 claim–evidence 和 number-consistency audit；
3. 完成 v2.4 中文上位机的界面、容错和离线回放；
4. 1 Hz 板卡和真实实验室数据到位后，另建新的数据合同、experiment ID、训练与部署包；
5. 不把公共数据 checkpoint 直接复制为实验室正式模型。
