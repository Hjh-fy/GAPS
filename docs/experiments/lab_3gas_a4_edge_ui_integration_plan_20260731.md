# 实验室三气体 A4 稳定段模型接入上位机 UI v2.2 验证计划

## 1. 目标与边界

目标是在不改变既有公共数据 Runtime v5 行为的前提下，为
`raspi_stm32_edge_ai_ui_v2_0` 增加实验室三气体“纯分类”运行模式，并验证
REC-A4-STABLE150 第 25 轮模型从离线检查点到树莓派上位机的数值一致性。

本计划只验证：

- 乙醛、甲烷、乙酸三分类；
- A4 稳定段窗口；
- 单窗口预测和同一暴露段内的累计共识；
- 模型、预处理、运行环境和输出的可审计身份。

本计划不验证：

- 浓度回归；
- 暴露开始后的全时间范围分类；
- 未经确认的 ADC 到电阻换算；
- 未经独立验证的置信度阈值 QC。

A4 的正式结果是 `359/360 = 99.72%`，但测试覆盖率为
`360/420 = 85.71%`。UI 和报告必须同时显示“稳定段专用”和覆盖边界，禁止
将 99.72% 表述为全时段准确率。

## 3. 冻结预处理合同

离线训练合同如下：

1. 输入物理量是六通道电阻值，不是 ADC 码值；
2. 时间轴插值到严格 1 Hz；
3. 每个暴露段使用通气前 300 s 空气段逐通道中位数作为 `R0`；
4. 计算相对电阻 `(R - R0) / abs(R0)`；
5. 使用宽度 5 的居中反射移动平均；
6. 形成 100 s 窗口，步长 50 s；
7. 使用仅由 P2 train 计算的均值和标准差做 z-score；
8. 输入顺序固定为 `CH1, CH2, CH4, CH6, CH8, CH9`。

实时端为保持与训练完全一致，居中 5 点滤波必须等待两个未来采样点，因此
至少引入 2 s 算法延迟。不得在未重新训练和复验前替换为因果滤波。

## 4. A4 在线门控语义

A4 是稳定段专家，不是全时段模型。为复现已评估范围：

- 暴露开始后先进入 `Unavailable / Stabilizing`；
- 只有窗口起点达到 `250 s` 后才允许组成正式 A4 测试窗口；
- 第一条正式结果最早在暴露开始约 `350 s` 后产生；
- 之后按 50 s 步长产生窗口预测；
- 暴露段切换、人工 Reset、模型包切换时必须清空累计共识；
- 空气基线不足 300 s、采样缺口超限或物理量合同不明时必须 fail closed。

`250 s` 是 A4 独立目标测试在排除校准窗口和 purge gap 后的首个窗口起点，
不等同于训练参数名中的 `stable150`。UI 必须显示实际门控值，避免误解。

## 5. 假设与验收标准

### H-A4-PKG：模型导出保持数值一致

- 原始 PyTorch 检查点与 TorchScript 对同一冻结输入的预测类别完全一致；
- 最大 logits 绝对差不超过 `1e-5`；
- 最大 softmax 概率绝对差不超过 `1e-6`；
- 部署包包含 manifest、模型、归一化、parity 报告、指标摘要和 README；
- manifest 明确 `task_type=classification`、`has_concentration=false`。

### H-A4-PRE：上位机预处理与离线构建器一致

- 在 P3 原始电阻回放上，严格 1 Hz、R0、中位数基线、相对电阻、5 点滤波、
  窗口切片和 z-score 的最大绝对差不超过 `1e-6`；
- 窗口起点、结束点和数量完全一致；
- 任一合同不满足时不调用模型。

### H-A4-UI：分类模式不制造浓度输出

- 三气体名称、单窗口概率、累计共识、阶段、窗口范围和模型身份首屏可见；
- 浓度卡片和浓度趋势图在分类模式下被替换，不显示 `0 ppm` 或伪浓度；
- CSV/JSON 审计记录保留三类概率、窗口预测、共识预测、模型/归一化 SHA；
- 原 Runtime v5 回放和 schema-v2 浓度模式回归测试保持通过。

### H-A4-CONS：累计共识可复算

- 共识定义为当前暴露段全部有效窗口 softmax 概率的算术平均；
- 共识类别是平均概率的 argmax；
- UI、CSV 与独立离线复算结果的概率最大绝对差不超过 `1e-6`；
- 不使用未经目标验证的 confidence threshold 自动给出 Accepted/Rejected。

### H-A4-PI：树莓派数值与性能可接受

- PC 与树莓派对同一回放窗口的类别完全一致；
- 概率最大绝对差不超过 `1e-5`；
- 树莓派单窗口推理 P95 延迟小于 500 ms；
- 800×480 无横向/纵向溢出，六张核心卡片全部可见；
- 公共 Runtime v5 模型包指纹保持不变。

### H-A4-LIVE：真实串口物理合同正确

开始真实采集验证前必须得到并冻结：

- 训练 CSV 的 `CH1/2/4/6/8/9` 与 STM32 帧字段的逐项映射；
- 六通道各自的分压方向、参考电压、ADC 满量程和负载电阻；
- ADC 饱和、开路、短路及非法电阻的处理规则；
- STM32 时间戳与主机接收时间的取舍。

未满足以上条件时，真实串口 A4 推理状态必须保持 `Unavailable`，只允许
离线回放或直接输入电阻值的旁路验证。

## 6. 执行顺序

### P0：合同与工件核验

冻结检查点、归一化、类别、预处理、A4 时间范围和硬件待确认项。

### P1：离线部署包与 parity

导出纯分类 TorchScript 包，完成检查点↔TorchScript、训练数组↔运行时推理
的数值一致性测试。P1 失败时不得进入 UI。

### P2：PC 上位机回放

增加 classification-only 适配器和 A4 预处理状态机，用 P3 原始电阻数据做
事件驱动回放；验证窗口输出、累计共识、CSV 审计和 800×480/1920 布局。

### P3：树莓派旁路与真实采集

先在树莓派用完全相同回放包验证数值和延迟。只有 H-A4-LIVE 的硬件合同
冻结并通过 ADC↔电阻实测 parity 后，才启用真实串口模型输出。

## 7. 失败回退

- 模型 parity 失败：停止，保留原始检查点，不发布 TorchScript；
- 预处理 parity 失败：停止，记录首个分歧阶段和数组；
- UI 回归失败：保留 Runtime v5 当前版本，实验室模式不启用；
- 硬件合同缺失：允许回放演示，不允许声称完成在线检测；
- A4 门控外收到请求：显示 `Unavailable / Stabilizing`，不回退到伪预测。
