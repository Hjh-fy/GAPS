# 实验室原始数据集与既有分割代码审查

**生成日期：** 2026-07-29

**数据目录：** `dataset/Dataset_self`

**参考代码：** `dataset/Dataset_self/filterpeak_clip_v4_P1_P2_usefirst.py`

**分析范围：** 三种正式气体、三个平台、v1/v2 原始 CSV；额外的“双戊烯”数据仅登记，不纳入三气体统计。
**证据状态：** 探索性诊断，不是正式模型结果。

## 1. 结论摘要

原始数据足以构建新的实验室训练主线，而且比之前的 `55 × 6` 单段归一化数据更适合浓度回归。

核心结论：

1. 三个平台的原始数据均包含时间列和 18 个传感器通道，时间轴完整、无缺失、无倒序、无大于 2 秒的采样缺口。
2. 实际采样率约为 1 Hz，但 Platform1 与 Platform2/3 的采样间隔不同。因此既有代码按“固定 3000 行”切分会造成平台相关的时间偏移。
3. `1_norm.csv` 不是逐段 Min-Max 归一化，而是固定量纲缩放；对当前选择的 CH1、CH2、CH4、CH6、CH8、CH9，基本等于原始值乘以 `1e-6`，没有破坏浓度幅值。
4. 旧的 `55 × 6` 数据则明显经过了后续逐段 0–1 处理。该后续脚本不在当前目录中。
5. 使用真实时间和通气前局部空气基线后，后五个浓度呈现很强的响应—浓度单调关系；这支持重新从原始数据构造回归样本。
6. 跨平台模型仍有明显域偏移，而同平台 v1/v2 之间的分类和标量校准效果明显更好。因此适合采用“跨平台全局模型 + 目标平台少量校准”的 GAPS 路线。

## 2. 数据清单

### 2.1 正式三气体矩阵

正式矩阵包含：

```text
3 platforms × 3 gases × 2 versions = 18 experiment folders
```

每个文件夹包含：

- `1.csv`：原始数据；
- `1_norm.csv`：固定量纲缩放数据；
- 18 个通道截图。

另外，Platform1 下有“双戊烯”v1/v2 两个文件夹。它们不属于当前三气体任务，应通过显式气体白名单排除，不能依赖目录遍历时的隐式规则。

### 2.2 原始文件格式

所有正式数据均为 19 列、无表头：

```text
Time, CH1, CH2, ..., CH18
```

推荐读取方式：

```python
pd.read_csv(
    path,
    header=None,
    names=["Time"] + [f"CH{i}" for i in range(1, 19)],
)
```

既有脚本使用 `pd.read_csv(self.file_path)`，若直接用于当前 `1.csv`，会把第一行数据误当作表头并丢失。虽然只影响一行，但正式适配器必须修正。

## 3. 时间轴与采样质量

### 3.1 平台采样差异

| 平台 | 文件数 | 行数范围 | 中位采样间隔 | 对应频率 | 时长范围 |
|---|---:|---:|---:|---:|---:|
| Platform1 | 6 | 18,691–19,900 | 约 1.035 s | 约 0.966 Hz | 19,329.5–20,565.2 s |
| Platform2 | 6 | 20,215–20,392 | 约 0.954 s | 约 1.048 Hz | 19,330.7–19,470.5 s |
| Platform3 | 6 | 20,207–21,669 | 约 0.955 s | 约 1.047 Hz | 19,327.0–20,751.2 s |

全量正式文件均满足：

- 时间严格递增；
- 无非正时间间隔；
- 无大于 2 秒的采样缺口；
- 无 NaN/Inf；
- 19 列结构一致。

因此原始数据质量足以按真实秒重采样。

### 3.2 实验节拍解释

文件总时长与以下协议吻合：

```text
初始空气 1800 s
然后每个浓度：
    目标气体 1200 s
    空气恢复 1800 s
每个浓度周期约 3000 s
共 6 个浓度周期
```

名义通气起点可写为：

```text
gas_start(k) = 1800 + (k - 1) × 3000, k = 1..6
gas_end(k)   = gas_start(k) + 1200
```

正式处理时应以该协议为先验，再在每个名义边界附近用多通道变化点细化实际气体到达时刻。

## 5. `1_norm.csv` 的真实含义

逐行对比表明，`1_norm.csv` 主要采用固定比例缩放：

- CH1–CH11：约乘 `1e-6`；
- CH12–CH16：约乘 `0.091827`；
- CH17–CH18：约乘 `0.001`。

对当前使用的六个电阻通道，`1_norm.csv` 与 `1.csv / 1e6` 等价，保留了不同浓度的绝对幅值关系。

这与旧的 `filtered_inverted.csv` 不同。后者在每段内大多从 0 上升到 1，说明还经历了额外的逐段归一化/反转/截断/降采样。

发现一个配对异常：

```text
platform1/20260130_Unit1_乙醛_v1
1.csv      = 19,114 行
1_norm.csv = 19,123 行
```

两者前 19,114 行时间完全对齐，但 `1_norm.csv` 多 9 行。其他配对行数一致。正式流程应选择一个权威原始源并记录文件哈希，避免混用两个长度版本。

## 6. 既有分割代码审查

### 6.1 当前算法

参考脚本的主要步骤：

```text
读取 CSV
-> 选择 CH1/CH2/CH4/CH6/CH8/CH9
-> Gaussian filter, sigma=64 samples
-> 每 3000 行为一个搜索区间
-> 每个区间、每个通道选一个最大峰
-> 对 P3 以后各通道峰位置取平均
-> P2 = P3 - 3000 rows
-> P1 = P3 - 6000 rows
-> 用 7 个点切成 6 段
```

脚本本身没有实现：

- 逐段归一化；
- 取负；
- 固定长度截断；
- 降采样为 55 点；
- 气体/浓度标签导出。

因此旧预处理目录的后半段生成逻辑目前仍缺失。

### 6.2 主要风险

#### 固定行数不等于固定秒数

3000 行在不同平台对应：

```text
Platform1: 约 3100 s
Platform2/3: 约 2865–2875 s
```

实际协议周期约 3000 s。固定行号会将平台采样差异误当作实验阶段差异。

#### P1/P2 依赖 P3

P1、P2 不由各自通气事件检测，而是从 P3 固定回推。只要 P3 偏移，前两个周期都会同步偏移。

#### 多通道峰的序号匹配不稳

大多数文件中，P3 的通道峰位置离散约百余点；但 Unit1/乙醛/v2 的 P3 通道跨度达到 1548 点。直接平均可能把不同物理事件的峰混在一起。

#### 最后一个分段较短

该算法得到的分段时长中位数约 2991 s，但最短仅约 2458 s。最终余数段经常落在文件结束附近，不能默认每段长度相同。

#### 过强平滑的可能性

`sigma=64 samples` 在当前约 1 Hz 数据上相当于约 60–66 秒平滑尺度。它适合抑制尖峰，但可能模糊气体到达和早期响应动力学。应将 sigma 换算成秒，并做 `0/16/32/64 s` 消融。

## 7. 原始响应的探索性证据

使用名义通气时间，定义：

```text
baseline: 通气前 300–30 s 的中位数
late gas response: 通气后 900–1170 s 的中位数
recovery probe: 通气后 2100–2400 s 的中位数
response = log(R_gas / R_baseline)
```

该计算仅用于 EDA，不代表最终固定窗口。

### 7.1 舍弃第一轮有数据支持

第一轮和第二轮使用相同最低浓度，但六通道响应存在明显差异：

| 气体 | position 1 vs 2 响应差异中位数 |
|---|---:|
| 乙醛 | 0.0903 log-ratio |
| 甲烷 | 0.1329 log-ratio |
| 乙酸 | 0.1394 log-ratio |

更重要的是，第一轮的恢复残差明显更高：

| 气体 | position 1 恢复残差中位数 | position 2 |
|---|---:|---:|
| 乙醛 | 0.1924 | 0.0757 |
| 甲烷 | 0.1816 | 0.0615 |
| 乙酸 | 0.1769 | 0.0539 |

因此建议：

- 原始数据不删除；
- position 1 标记为 `warmup_qc_only`；
- 正式训练、校准和测试仅使用 position 2–6。

### 7.2 浓度单调性很强

在 position 2–6 中，针对每种气体分别计算：

```text
3 units × 2 versions × 6 channels = 36 个浓度排序
```

每种气体均有 35/36 个组合满足：

```text
Spearman rho(abs(response), concentration) >= 0.7
```

多数通道组合达到完全单调 `rho=1.0`。

三个例外：

- Unit1/甲烷/v2/CH6：rho = -0.1；
- Unit1/乙醛/v2/CH6：rho = -0.1；
- Unit2/乙酸/v1/CH2：rho = 0.1。

这表明原始数据非常适合浓度回归，同时也说明不应让单个异常通道主导预测。

## 8. 可学习性诊断

### 8.1 跨平台直接泛化

基于局部基线的早期/中期/末期响应特征，留一平台气体分类 Macro-F1 约为 `0.413–0.547`。每气体浓度回归在新平台上也明显退化。

结论：不同板子的响应幅值/通道签名差异很强，不能只训练一个全局模型后直接零样本部署。

### 8.2 同平台跨 v1/v2

同平台使用一个 version 训练、另一个 version 测试：

- 6 个气体分类方向中，5 个方向 Accuracy/Macro-F1 = 1.0；
- 另一个方向约为 0.867。

使用每平台、每气体的五个浓度拟合简单标量响应校准，再测试另一个 version：

| 气体 | 跨 version MAE 范围 |
|---|---:|
| 乙醛 | Unit1/2 为 0.018–0.023 ppm；Unit3 为 0.127–0.136 ppm |
| 甲烷 | 264–554 ppm |
| 乙酸 | 2.63–6.92 ppm |

这些结果每个方向只有 5 个测试浓度，不能当作正式性能，但清楚支持“全局表示 + 目标板子校准”的系统结构。

## 9. 推荐的新预处理流程

### 9.1 输入与时间处理

```text
1.csv，无表头
-> 命名 Time + CH1..CH18
-> 检查时间单调、缺失和异常间隔
-> 先按真实时间插值到统一 1 Hz
-> 再进行以秒为单位的滤波和切窗
```

不建议把约 1 Hz 数据上采样到 10 Hz 来伪造高时间分辨率。

### 9.2 分段

对每个 position：

1. 使用协议给出的名义 `gas_start`；
2. 在名义起点附近用六通道稳健变化分数细化实际 onset；
3. 保存名义时间、检测时间、偏差和不确定性；
4. 若各通道事件位置分歧过大，标记为 `review`，不能静默取平均；
5. 保留完整空气、气体和恢复阶段。

### 9.3 特征

主候选：

```text
G = 1 / R
relative_conductance = (G - G0) / G0
```

对照候选：

```text
signed_log_ratio = log(R / R0)
```

不再执行逐浓度段 Min-Max。也不强制对整段“取负”；应保留符号，必要时使用预先固定的通道方向表。

### 9.4 窗口

建议先重采样到 1 Hz，再使用：

```text
window_size = 100 points = 100 s
step_size = 20 or 50 s
```

分别标记：

- `early_response`：0–300 s；
- `middle_response`：300–900 s；
- `late_response`：900–1200 s；
- `recovery`；
- `air`.

浓度回归主结果先使用中后期窗口；早期窗口用于评估部署时“多早能够稳定预测”。

每个 1200 秒气体段若采用 100 秒窗口、50 秒步长，可得到约 23 个窗口。90 个有效暴露约产生 2070 个气体窗口，但统计独立单位仍是 90 个 exposure，不能按窗口随机切分。

## 10. 模型和联邦划分建议

### 10.1 新的输入与标签

```text
input shape: (N, 100, 6)
gas classes: acetaldehyde, methane, acetic_acid
clients: platform1, platform2, platform3
```

当前公共模型的 `100 × 8` 输入层和四分类头不能直接复用。可以比较：

1. 实验室数据从头训练的六通道轻量模型；
2. 公共骨干 + 可学习 6→8 输入适配器 + 新三分类头；
3. 仅迁移低层骨干、重新训练全部分类和回归头。

由于采样率、硬件和气体集合均变化，迁移学习必须作为对照假设，不能预设一定优于从头训练。

### 10.2 推荐评估方向

严格跨平台：

```text
P1 + P2 -> P3
P1 + P3 -> P2
P2 + P3 -> P1
```

对目标平台：

- 较早日期的完整批次用于 calibration；
- 较晚日期的完整批次用于 test；
- 不根据 v1/v2 名称猜测时间先后，按文件日期决定；
- 所有来自同一 exposure 的窗口必须留在同一 split。

需先确认 `platform3/20240416_Unit3_乙酸_v1` 是否确实为 2024 年。若是文件名笔误，应在 manifest 中修正并保留原始名称；若属实，则它是长期漂移样本。

### 10.3 空气数据

空气窗口不应强行作为三气体分类器的第四类浓度回归标签。推荐增加独立的：

```text
gas_present: air vs gas
```

然后再执行：

```text
gas type classification
-> gas-specific concentration regression
-> per-platform calibration
-> QC
```
