# 开发梯度诊断提案 · 未执行

若要识别所提分解，需要开发起点处的梯度。仅继续分析已有 CE 曲线无法替代这一信息。下述预算是可审阅的最小建议，任何数值访问仍需新的独立授权。

第一部分只诊断既定四个案例：第 5 轮 Ethanol、Ethylene、Methane，以及第 1 轮 Methane 对照。每个案例使用该类别全部六次开发暴露，不根据本轮损失挑选或删除暴露。两轮 Methane 共用同一组六文件，所以需重新打开的不同原始文件为 18 个，全部属于已封存 Gate 3 身份。

| 访问 / 计算 | 固定预算 |
| --- | --- |
| 原始信号 | 最多打开 18 文件各一次，重哈希并与 Gate 3 输入窗口 SHA 核对 |
| 模型 | 第 1、5 轮 B4 aggregated 两个严格加载；Δ 从 Gate 3 封存的完整位移读取 |
| 参数 | 原 36 个可训练浮点张量、22,765 个标量；别名按对象去重，顺序与原合同相同 |
| 计算 | float64、CPU eval、inference 关闭以允许梯度，梯度上下文固定；无需 optimizer |
| 起点梯度 | 4 案例 × 6 暴露 = 24 次前向及反向，每次 21 窗，共 504 个窗口梯度样本 |
| 损失 | 暴露内部窗口等权，再对同类六暴露等权 |
| 输出 | 每暴露 g_dev 范数、g_dev·Δ、方向、类均值与两个分解项，和冻结 R_dev 对照 |

只读地计算开发梯度，将它明确标为事后解释量。它不进入 A/B 求解、不进入任何候选位移、不用于拟合可靠性阈值，也不用于新的 Day22 评价。

若起点结果仍不足以解释路径，可另行授权在原有 α=0.25、0.5、1.0 上计算开发梯度。追加预算为 72 次前向/反向、1,512 个窗口梯度样本，总计 96 次、2,016 个样本；同一进程内复用已校验的 18 份输入，保持原尺度。有限路径点也只提供离散路径描述。该部分同样未执行。
