# Phase3.9 执行计划

以 Phase3.8R 固定提交 08db3e52e53657169660acd6dfb23fe5209fafa8 和 Phase3.7 已封存实现为来源。在现有独立研究 worktree 建立 PC-F32-CPU-SINGLE-v1。

1. 在运行前锁定源码、六个分类端点、四个回归头、scaler、软件配置和 Calibration 身份。合成输入固定四个整数公式窗口，覆盖零值、缓变、交替和局部脉冲。它们只用于数值验收。
2. golden 工作者直接通过冻结 P37 ClassifierAdapter、ExtractorAdapter、SVRAdapter 和 JointBridge 生成参考。每窗六次预测路由，另行逐个检查四个回归头。独占写入文件。父进程在 golden 退出后记录日志、账本及输出 SHA 并封存，再启动独立复验进程。
3. 复验固定执行首次加载、同进程重复、完整重新加载三遍，并对比独立进程 golden。逐分量分类容差沿用 1e-4/1e-5，同时要求同合同的 logits 逐字节一致、argmax 完全一致、71D 逐字节一致。SVR 沿用 1e-10/1e-12，版本、支持范围、raw/clip 关系精确核对。
4. 在复验进程内执行预定异常。冻结桥接负责输入、分类、特征与回归异常。外层候选加载负责四头 scaler SHA 和完整资产验证，失败时已有快照保留，冷启动失败时返回 UNAVAILABLE。使用真实加载路径注入缺失文件，scaler 异常只改变独立测试副本。
5. 每个工作者从加载项目及数值模块前记录 Python open 审计事件。同步持久化允许、拒绝及受包装 API 的成功或失败，关联阶段和请求。以实际 forward hook、原 SVR 入口与原特征入口记录调用账本。日志、PID、允许输入、预定拒绝、恢复失败和账本不能闭合时保持 BLOCKED。
6. 只读独立审阅证据，分列本合同与历史 batch128 验收。发布精简审阅件、锁、汇总、日志和账本摘要及哈希。完整逐窗参考和模型留本地。

历史 Day22 数据、完整预测日志和旧五条漂移数值均在本轮工作者读取范围之外。日志能力限定为 Python 审计事件和包装 API，可见范围不等同 OS 文件系统审计。
