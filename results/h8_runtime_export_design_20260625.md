## Why H8 Needed Extra Runtime Work

H2.3 is already supported by the current runtime artifact because it only needs:

- target MLP direct models;
- target Ridge direct models;
- C4 route rescue gate.

H8 needs additional inference-time features:

- `H1_source_ridge_ppm`;
- `H2_source_per_gas_mlp_ppm`;
- `H3_source_shared_mlp_ppm`.

Those are generated by source-trained lightweight heads in `run_source_augmented_target_ridge_eval.py`, then appended as `srcpred_*` features before fitting target Ridge. The previous runtime did not serialize or evaluate these source-head submodels; this is now implemented for the H8 candidate.

## Required Artifact Schema

The H8 artifact now adds a new optional section to `rich_residual_candidate.json`:

```json
{
  "source_aug_target_ridge_policy": {
    "schema": "source_aug_target_ridge.v1",
    "enabled_clients": ["C3", "C4", "C5"],
    "switch_rule": {"type": "pred_class_equals", "class_id": 1},
    "source_heads": {
      "ridge_per_gas": [...],
      "mlp_per_gas": [...],
      "shared_mlp": {...}
    },
    "target_aug_ridge_models": [...],
    "feature_names": [...]
  }
}
```

The target augmented Ridge feature names must match the training feature dictionary:

- all `rich_feature_dict` keys;
- `srcpred_H1_source_ridge_ppm`;
- `srcpred_H2_source_per_gas_mlp_ppm`;
- `srcpred_H3_source_shared_mlp_ppm`.

## Runtime Apply Order

The desired runtime order is:

1. C4 route rescue if its gate fires;
2. H8 source-aug CO specialist if:
   - client is enabled;
   - `pred_class == CO`;
   - source-aug policy is present and valid;
3. existing H2.3 target MLP/Ridge policy;
4. older residual policy fallback;
5. original `final_ppm`.

This preserves H2.3 behavior for non-CO routes and only overrides predicted-CO rows.

## Implementation Steps

1. Add serialization helpers:
   - source Ridge per-gas: use existing `RidgeHead.to_json()`;
   - source per-gas MLP: reuse `serialize_mlp_head()` from `export_hybrid_mlp_ridge_deployment_candidate.py`;
   - source shared MLP: same MLP serialization, with gas one-hot appended at runtime.
2. Add export script:
   - fit source heads using C1/C2 train/calibration;
   - fit source-aug target Ridge on C3/C4/C5 calibration;
   - load H8 calibration selector profile;
   - write `source_aug_target_ridge_policy`.
3. Extend `gaps_deploy/rich_residual.py`:
   - compute `rich_feature_dict` equivalent using `_target_ridge_features`;
   - run source per-gas heads using current `pred_class` as route;
   - run shared source MLP with route one-hot;
   - append `srcpred_*`;
   - apply selected target augmented Ridge model.
4. Validate parity:
   - compare runtime `co_corrected_ppm` against `results/co_only_source_aug_hybrid_stratcalval_20260625/co_only_source_aug_hybrid_predictions.csv`;
   - expected `num_mismatch = 0`;
   - target tolerance `max_abs_diff < 1e-6`.

## Promotion Rule

H8 can become the default only if all are true:

- runtime parity passes;
- no hidden test-only selection is introduced;
- ALL RMSE and/or CO metrics improve against H2.3;
- ALL NRMSE and nonCO degradation are accepted by an explicit profile rule, not silently ignored.

H2.3 remains the balanced mainline unless we explicitly accept H8's NRMSE/nonCO trade-off. H8 is now deployable as a CO-specialist candidate.
